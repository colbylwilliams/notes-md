## Welcome Contributors!

Thank you for your interest in contributing to Notes MD! This document provides guidelines and information for contributors.

## Getting Started

1. Fork the repository
2. Clone your fork locally
3. Follow the [Developer Guide](./developer-guide.md) for setup
4. Create a new branch for your changes
5. Make your changes and test them
6. Submit a pull request

## Types of Contributions

We welcome various types of contributions:

- 🐛 Bug fixes
- ✨ New features
- 📝 Documentation improvements
- 🎨 UI/UX enhancements
- 🧪 Test improvements
- 🔧 Infrastructure and tooling

## Development Workflow

### 1. Setting Up Development Environment

Follow the [Getting Started](./getting-started.md) guide to set up your development environment.

### 2. Making Changes

- Create a descriptive branch name (e.g., `feature/add-search`, `fix/note-deletion-bug`)
- Make your changes in logical, atomic commits
- Write clear commit messages
- Include tests for new functionality
- Update documentation as needed

### 3. Testing

- Run the existing test suite: `npm test`
- Add tests for new features or bug fixes
- Ensure all tests pass before submitting

### 4. Code Style

<!-- TODO: Document specific code style guidelines -->

- Follow the existing code style
- Use TypeScript for type safety
- Run the linter: `npm run lint`
- Use meaningful variable and function names

## Pull Request Process

1. Update documentation if needed
2. Add tests for new functionality
3. Ensure all tests pass
4. Update the README.md if your changes affect usage
5. Create a pull request with a clear description

### Pull Request Guidelines

- Provide a clear description of the changes
- Reference any related issues
- Include screenshots for UI changes
- Keep changes focused and atomic
- Respond to review feedback promptly

## Reporting Issues

### Bug Reports

When reporting bugs, please include:

- Steps to reproduce the issue
- Expected behavior
- Actual behavior
- Environment details (browser, OS, etc.)
- Screenshots if applicable

### Feature Requests

For feature requests, please provide:

- A clear description of the feature
- Use cases and benefits
- Any relevant mockups or examples
